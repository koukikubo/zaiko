# ZAIKO 要件定義書

- バージョン: 0.1
- ステータス: 要件整理中
- 対象: 飲食店向け在庫・発注管理システム

## 1. 開発背景

現在の飲食店業務では、食材の在庫確認や
発注管理を紙ベースで行っている。

特にGW・お盆・年末年始などの繁忙期は、
仕入先の休業日を考慮した発注が必要になる。

また、スタッフのポジション異動により、
過去の発注判断や在庫状況を把握しづらく、
経験豊富な先輩スタッフへの確認が必要になる。

## 2. 開発目的

- 在庫確認・棚卸作業の効率化
- 日次在庫と食材状態の記録
- ロス数量・理由の可視化
- 発注・承認・納品履歴の一元管理
- 経験の浅いスタッフの発注判断支援
- 過去の繁忙期との実績比較

## 3. システム構成

### Backend

- Ruby on Rails 8.1（APIモード）
- Ruby 3.4
- PostgreSQL
- RSpec

### Infrastructure

- Docker
- Docker Compose
- GitHub Actions（CI）

### Frontend

- React Native
- Expo
- TypeScript
- iOS / Android対応

### 認証

- Google OAuth 2.0 + OpenID Connect
- Authorization Code Flow + PKCE
- Rails側でスタッフの認証・認可を検証
- 未登録・無効化スタッフの利用は禁止

## 4. 利用者と権限

### 利用者

- 一般スタッフ
- 発注承認者
- 管理者

### 権限管理

- 基本権限はスタッフマスタで管理する
- 担当ポジションと発注承認権限を分離する
- 異なるポジションでも許可された発注は承認可能
- 承認権限は管理者が明示的に付与する
- 権限がない操作はRails側で拒否する
- 自己承認は原則禁止する
- 権限付与・変更・失効の履歴を保持する

## 7. 開発フェーズ

### Phase 1-A 認証・マスタ管理

Google認証、スタッフ、ポジション、
食材、保管場所の管理。

### Phase 1-B 日次在庫・ロス管理

日次在庫確認、棚卸、
食材状態、ロス記録。

### Phase 1-C 在庫照会・帳票・メンテナンス

在庫照会、PDF/CSV出力、
在庫データの訂正・監査。

### Phase 2 発注・承認・納品

発注案、承認、FAX帳票、
納品・検品、在庫移動。

### Phase 3 分析・発注支援

過去実績、繁忙期比較、
推定使用量、発注支援。

## 8. 開発ルール

- バックエンドを先に実装する
- フロントエンドは後続フェーズで開発する
- Issueに実装範囲と完了条件を記載する
- TDDで実装する
- Gitmoji＋日本語でコミットする
- PRでCodexレビューを受ける
- 必須CIが成功してからマージする
- マージ後は作業ブランチを削除する
- 追加仕様は別Issueで管理する
