# ZAIKO 棚卸・在庫算定ルール

- 対応Issue：#6
- 対応要件：FR-01、FR-03、FR-04、FR-05
- 対象フェーズ：Phase 1
- ステータス：詳細設計中

## 1. 目的

日次棚卸、在庫照会、ロス記録について、
データの記録単位と状態遷移を定義する。

POSとの自動連携を前提とせず、
確認済み実在庫と理論在庫を区別する。

## 2. 棚卸の管理単位

### 基本方針

- 棚卸ヘッダーはinventory_countsで管理する。
- 棚卸明細はinventory_count_linesで管理する。
- 基本単位は店舗×営業日×保管場所とする。
- 1つの棚卸に複数食材の明細を登録できる。
- 1つの棚卸を複数スタッフで分担できる。
- 棚卸ヘッダーに責任ポジションを固定しない。
- 棚卸責任は保管場所×食材ごとに管理する。
- 実際の棚卸実施者は明細ごとに記録する。

### 同一営業日の複数回棚卸

同一営業日・同一保管場所での再棚卸を認める。

採用方式：revision_noによる版管理

- 初回棚卸はrevision_no=1とする。
- 2回目以降は前回確定版を残したまま新しい版を作成する。
- 第2版以降の再棚卸・訂正理由は任意とする。
- 理由が入力された場合は履歴として保存する。
- 理由の有無にかかわらず変更者・変更日時・変更前後の数量を追跡する。
- 通常の再棚卸はdraftとして開始できる。
- 確定後の画面編集では、保存時に新しいconfirmed版を自動作成する。
- 過去のconfirmed版は更新・削除しない。
- 1営業日・1保管場所につきdraftは最大1件とする。
- confirmedの数量や明細は直接更新しない。
- 新しい版は前回の明細を引き継いだ完全なスナップショットとする。
- 最新在庫照会では同一営業日の最大確定revision_noのみ採用する。
- 過去の確定版は履歴として参照可能にする。

## 3. 営業日と記録日時

- business_dateは店舗の営業日を表す。
- created_atはシステム上の作成日時を表す。
- counted_atは実際に食材を数えた日時を表す。
- confirmed_atは棚卸を確定した日時を表す。
- 営業日と実際の記録日は一致するとは限らない。
- タイムスタンプはDBに日時として保存する。
- 画面表示時は店舗のタイムゾーンを考慮する。

深夜営業で営業日が日付をまたぐ場合の判定基準は、
店舗設定との整合性を確認して確定する。

## 4. 棚卸状態

### 状態候補

| 状態   | コード    | 意味                       |
| ------ | --------- | -------------------------- |
| 下書き | draft     | 数量を入力・編集できる     |
| 確定   | confirmed | 棚卸を正式な実績として扱う |

### 基本状態遷移

- 新規作成時はdraftとする。
- draftは保存・再編集できる。
- draftからconfirmedへ変更できる。
- confirmedの数量を通常の編集操作で上書きしない。
- 確定処理はトランザクション内で実行する。
- 確定者と確定日時を保存する。
- 確定後の訂正理由は任意入力とする。
- 訂正前後の数量・訂正者・訂正日時を必ず追跡できるようにする。

確定後の訂正は、revision_noを増やした新しい棚卸ヘッダーと
明細の完全スナップショットで管理する。
過去の確定版は更新・削除しない。

## 5. 棚卸明細

- 棚卸対象はstock_location_item_idで特定する。
- 実測数量はmeasured_quantityで保存する。
- 数量の基準単位はitems.base_unitとする。
- 数量はdecimal(12,3)を使用する。
- 負数は登録できない。
- NULLは未確認を表す。
- 0は確認済みの在庫数量0を表す。
- 棚卸実施者と実施日時を記録する。
- 入力者と実施者が異なる場合も区別する。
- 棚卸時点の責任ポジションを履歴に保持する。
- 同一棚卸内の同一保管場所別食材は重複登録しない。

## 6. 在庫照会との関係

- 在庫照会には確定済みの棚卸のみ使用する。
- 下書き数量を確定在庫として表示しない。
- 保管場所×食材単位で最新の確認済み数量を取得する。
- 未確認の食材は数量0として扱わない。
- 複数ポジションが同じ食材を使用しても、
  物理在庫を二重計上しない。
- 最終確認日時と確認スタッフを追跡可能とする。

## 7. ロス記録との関係

- ロスはloss_recordsで記録する。
- ロスの発生日時と登録日時を区別する。
- ロスの数量・理由・報告スタッフを保持する。
- ロスを記録しても、直近の実測棚卸数量を
  自動的に書き換えない。
- ロス数量を推定使用量の計算で利用する場合、
  二重控除を防ぐ算定式を別途定義する。

## 8. 確定した設計判断と実装条件

### 確定した設計判断

- 同一営業日の棚卸はrevision_noで版管理する。
- 確定後も画面から訂正できる。
- 訂正後は新しいconfirmed版を作成する。
- 訂正理由は任意入力とする。
- 未確認数量NULLを含む棚卸は確定できない。
- 実測数量0は確認済みとして扱う。
- 同一店舗の有効なスタッフは代理棚卸できる。
- 棚卸中の食材・責任ポジション変更を許可する。
- 品質状態はgood、caution、discard_candidateとする。
- ロス記録は実測棚卸数量を直接変更しない。
- 最新確定版だけを在庫照会の対象とする。

### 営業日の扱い

- business_dateは利用者が対象営業日を指定できる。
- 初期表示は店舗タイムゾーンの日付とする。
- 深夜営業の場合、前営業日を手動選択できる。
- Phase 1では営業日切替時刻の自動判定設定を設けない。
- 実際の計測日時と対象営業日は別々に保持する。

### 実装時の整合性条件

- 同一店舗・営業日・保管場所のdraftは最大1件とする。
- draftと確定後訂正の競合を防止する。
- 保管場所の無効化前に作成したdraftは継続・確定を許可する。
- 確定版の直接UPDATEは禁止する。
- 変更前後の履歴を保持する。
- 店舗境界は複合FKと認可で保証する。

### 後続設計で扱う事項

- 高度な履歴検索
- 履歴検索結果の一括CSV・PDF出力
- 推定業務使用量の本格的な算定
- 店舗ごとの詳細な操作権限カスタマイズ

## 9. 棚卸明細の記録元と履歴保全

### 記録元の区別

- direct：システム上で実測・入力した記録
- paper：紙から転記した記録
- carried_forward：前版から変更せず引き継いだ記録
- corrected：前版を訂正した記録

### 記録の必須条件

- 実測数量NULLは未確認を意味する。
- 実測数量0は確認済みの数量0を意味する。
- directでは実際の計測者と計測日時を記録する。
- paperでは実際の計測者が不明でもよいが、
  入力者と入力日時を必ず記録する。
- 計測者または計測日時が不明な紙の記録では、
  記録元の補足を必須とする。
- 確定時には必須明細がすべて確認済みであること。
- 基準単位と数量精度の整合性を検証する。

### 再棚卸・訂正時の記録

- 訂正版は前版とは別のinventory_count_idを持つ。
- 前版の数量を引き継ぐ明細にはsource_line_idを設定する。
- 引き継いだ明細は新たに実測したものとして扱わない。
- 数量や品質を訂正した場合はcorrectedとして記録する。
- 実際に数え直した場合はdirectまたはpaperで記録する。
- 確定版は完全なスナップショットとする。
- 過去版は変更せず履歴として保存する。
- 履歴照会では元の計測日時と入力日時を区別する。

### 棚卸責任の変更

- 新しい実測時には現在の棚卸責任を取得する。
- 過去版から引き継いだ実測は当時の責任情報を維持する。
- 責任ポジションの変更は監査履歴に記録する。
- 確定後に責任ポジションが変わっても過去の明細を書き換えない。

### DBとServiceの責務

- FK・UNIQUE・CHECKで保証できる条件はDBで強制する。
- 店舗・保管場所の一致は複合FKで保証する。
- 親棚卸の状態、前版との関係、代理棚卸権限、
  記録元の詳細条件はServiceで検証する。
- 明細変更と棚卸確定処理は共通のロック規約に従う。

## 10. ロス記録・訂正・在庫算定ルール

### ロスの管理単位

- ロスは保管場所×食材単位で記録する。
- ロス数量は食材の在庫基準単位で記録する。
- 発生営業日、発生日時、報告者、登録者を区別する。
- ロス記録は実測棚卸数量を直接変更しない。

### ロス記録の状態

| 状態     | コード   | 意味             |
| -------- | -------- | ---------------- |
| 登録済み | recorded | 有効なロス実績   |
| 取消済み | voided   | 集計対象外の履歴 |

- 新規登録時はrecordedとする。
- recordedからvoidedへの変更のみ許可する。
- voidedからrecordedへ直接戻さない。
- 訂正では元記録をvoidedにして新規記録を作成する。
- 訂正元と訂正後はreplaces_loss_record_idで関連付ける。
- 訂正・取消理由と操作スタッフを記録する。

### ロスと実測在庫

- 棚卸で数えた実測数量は変更しない。
- 廃棄済み数量が実測棚卸に反映されている場合、
  そのロスを再度実測数量から減算しない。
- ロス集計ではrecordedのみを採用する。
- 取消済みロスは通常の数量集計から除外する。
- 計測前後の数量を用いた分析では、
  ロスの発生時点と棚卸の計測時点を照合する。

### 推定使用量

推定業務使用量 = 期首実測数量 + 入庫数量 + 移動入数量 - 移動出数量 - 期末実測数量 - 期間中のロス数量

期首・期末が独立した実測値であり、
その他の在庫増減が適切に処理されている場合に限る。

- 引き継ぎ数量を新たな実測値として扱わない。
- 未確認数量を0として計算しない。
- 計測期間外のロスを集計に含めない。
- 必要な入出庫データが存在しない場合は、
  推定値の信頼性に制約があることを明示する。
- 負の推定使用量が算出された場合は、
  データ整合性の確認対象とする。

Phase 1では確定した推定使用量として運用せず、
後続の分析設計で算定条件を確定する。

### 重複・競合防止

- request_keyで同一操作の重複送信を防止する。
- 同じ食材・営業日の別ロス登録は許可する。
- 取消と訂正の同時操作をロックで保護する。
- 取消・訂正・監査記録をトランザクションで管理する。

### 履歴照会

- 過去のロス一覧・詳細を確認できる。
- 食材・場所・数量・理由・発生日時・報告者を表示する。
- 訂正前後の記録を関連付けて表示できる。
- 取消済みも履歴から参照できる。
- 他店舗の記録は参照できない。

## 11. 操作権限・棚卸対象・基本履歴照会

**対応Issue：** #6

**対応要件：** FR-03、FR-04、FR-05

### 操作権限

Phase 1では、店舗内の柔軟な運用を優先する。

- 有効な店舗スタッフは棚卸を作成できる。
- 有効な店舗スタッフは棚卸数量を入力・変更できる。
- 担当ポジションにかかわらず代理棚卸を認める。
- 有効な店舗スタッフは棚卸を確定できる。
- 棚卸確定時に管理者承認を要求しない。
- 確定済み棚卸も編集できる。
- ロス記録の登録・訂正・取消を許可する。
- 同一店舗のスタッフは基本履歴を閲覧できる。
- 他店舗のデータ参照・変更は禁止する。
- 担当ポジションは作業責任を示す情報であり、
  操作を拒否するための固定権限には使用しない。

将来的に店舗別の操作権限設定を導入できる構造とするが、
Phase 1では権限管理画面を追加しない。

### 確定後の変更

- 確定後も画面から数量・品質等を編集できる。
- 変更時に追加の承認は要求しない。
- 保存時に新しいrevision_noの確定版を作成する。
- 以前の確定版は履歴として保存する。
- 変更前後の数量を比較できる。
- 変更者と変更日時を保存する。
- 訂正理由の入力は任意とする。
- 新版の保存はトランザクション内で実行する。
- 同時更新による意図しない上書きを防ぐ。

通常の下書き保存と、確定後編集による即時反映を区別する。

### 棚卸途中の変更

- 棚卸開始後も食材を追加できる。
- 棚卸開始後も責任ポジションを変更できる。
- 新しく追加した食材は未確認数量NULLで追加する。
- 入力済みの食材を対象外にするときは確認を表示する。
- 対象外にした下書き明細の変更履歴を記録する。
- 既存の入力済み数量を自動的に0へ変換しない。
- 責任ポジション変更後も実施者と計測日時を保持する。
- 過去の確定済み明細は変更しない。
- 棚卸の確定時には最新の対象食材との整合性を検証する。
- 物理的な在庫が残る食材を対象外にする場合は、
  在庫移動・ロス・数量訂正等が必要であることを警告する。

### 保管場所の無効化と棚卸継続

- 棚卸がdraft中でも保管場所を無効化できる。
- 無効化時には作業中の棚卸が存在することを通知する。
- 無効化前に作成したdraftは編集・確定を継続できる。
- 無効化後、その保管場所の新規棚卸作成は禁止する。
- 確定済み棚卸や過去の明細は変更・削除しない。
- 在庫照会では無効化前の確定履歴も参照可能とする。

### 基本履歴照会

Phase 1で実装する機能：

- 棚卸履歴一覧の表示
- 直近30日を初期表示
- 営業日・保管場所での基本的な絞り込み
- 棚卸詳細の表示
- 食材名・数量・単位・品質状態の表示
- 実施スタッフ・入力スタッフ・確認日時の表示
- 訂正前後の数量比較
- 過去の確定版の閲覧
- 同一店舗内の履歴閲覧
- ページネーション

後続実装とする機能：

- 複数条件を組み合わせた高度な検索
- スタッフ別・ポジション別の横断分析
- 食材別の長期推移グラフ
- 履歴検索結果の一括CSV・PDF出力

棚卸記入用PDF・在庫CSVの基本出力は
FR-02の仕様に従い、履歴検索結果の出力とは区別する。
