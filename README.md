# 飲食店向け在庫・発注管理システム

## 開発背景

飲食店では、食材の在庫確認や発注管理を
紙ベースで行うことが多い。

通常の発注だけでなく、GW・お盆・年末年始など、
仕入先の休業に合わせた変則発注も発生する。

また、スタッフが新しいポジションを担当する際、
過去の在庫数や発注判断を把握しにくく、
先輩スタッフの経験に依存する課題がある。

## 解決したい課題

1. ポジション別の在庫確認を効率化する
2. 在庫数量と食材の状態を毎日記録する
3. 廃棄・破損等のロスを可視化する
4. 過去の繁忙期の発注・在庫実績を参照する
5. 発注案を責任者が承認できるようにする
6. 発注数と実際の納品数の差を把握する
7. 棚卸表を出力し、実在庫との差を分析する

## システムの基本方針

- POSレジとの連携を必須としない
- 食材の在庫と状態は日次で確認する
- ポジション別に担当責任を持つ
- 発注案は承認後に発注する
- 在庫・発注・納品・承認の履歴を保持する
- Coletteとは独立したシステムとする

## 開発ルール

1. 要件定義・詳細設計を確認してから実装する
2. 先に失敗するテストを作成する（TDD）
3. テストを通すための最小限の実装を行う
4. リファクタリング後に再テストする
5. 仕様追加・変更はIssueで管理する
6. バックエンドのコードは手動で確認する
7. テスト成功後にコミット・プッシュする
8. mainへの統合はレビュー後に行う
